# 决策记录：快看视频 QuickVideo

> 状态：已确认（2026-07-21）

## D-001：首发形态为本地 macOS 软件

- **决定**：先做仅在 Apple Silicon Mac 上运行的个人桌面软件，不先建设网页服务。
- **原因**：项目发起人本地使用 Mac；可优先验证价值、隐私体验与工作流，避免过早承担服务器和 GPU 成本。
- **后续影响**：安装、模型管理、任务进度与本地文件存储将作为产品能力设计；Windows、Linux 和移动端不进入首版。

## D-002：首版转写后端使用 whisper.cpp

- **决定**：本地语音转文字采用 `whisper.cpp`，针对 Apple Silicon 的本地运行环境优化。
- **原因**：首版主要在 Mac 上运行；转写需要离线可用并避免云端成本。
- **后续影响**：转写模块必须抽象统一输入输出，避免业务层绑定具体实现。

## D-003：未来可替换为云端 faster-whisper

- **决定**：后续上线或需要更快处理时，使用在线 GPU 的 `faster-whisper` 服务；首版不自建 GPU 服务。
- **原因**：将成本留到有真实用户与使用量后再承担，并保留更快长视频处理的升级路径。
- **后续影响**：转写结果统一包含时间范围、文本、识别语言与可选置信信息；本地和云端转写应可无缝切换。

## D-004：链接来源先支持 YouTube 与 Bilibili

- **决定**：首版链接输入仅面向 YouTube 与 Bilibili；同时支持用户导入本地视频或音频文件。
- **原因**：这两个平台是项目发起人最高频的内容来源；本地文件导入提供最稳定、最可控的基础路径。
- **后续影响**：其他平台不进入首版承诺；链接处理需设计为可更新的独立能力。

## D-005：字幕采用“平台优先、本地转写兜底”

- **决定**：依次优先使用人工字幕、平台自动字幕，最后才进行本地语音转文字。
- **原因**：优先字幕能缩短等待时间、减少本机计算，并通常提供更准确的时间轴。
- **后续影响**：产品需要标明字幕来源与处理状态，并在没有可用字幕时提供清楚的转写反馈。

## D-006：处理中文、英文和中英混合视频

- **决定**：首版支持中文、英文及中英混合内容；目标视频时长为 20 分钟到 2 小时。
- **原因**：符合项目发起人的主要视频来源和使用习惯。
- **后续影响**：测试集必须覆盖两种语言、混说、短视频与两小时长视频。

## D-007：不以“完整视频下载与保存”作为卖点

- **决定**：产品对外定位为视频理解与知识整理工具，不宣传或提供“下载任意视频、保存完整视频”的产品承诺。
- **原因**：避免产品被定义为下载器，降低版权、平台条款、兼容性和售后风险。
- **后续影响**：用户入口为“分析链接”；如确需媒体处理，仅作为后台临时步骤，完成后默认删除临时音视频。

## D-008：明确使用边界

- **决定**：只允许用户处理其拥有、已获授权或平台允许处理的内容；不支持 DRM、付费、会员、登录或其他访问限制的绕过。
- **原因**：商业发布必须将版权和平台使用边界置于核心产品规则中。
- **后续影响**：应用内应提供清晰提示和隐私说明；本地文件导入是长期保留的主路径。

## D-009：结果而非媒体是长期资产

- **决定**：默认保留视频元数据、字幕、章节摘要和 Markdown 导出；不默认保留完整视频或音频。
- **原因**：降低磁盘占用和内容风险，使产品价值集中在知识沉淀。
- **后续影响**：未来可将结构化笔记作为现有信息资源站的增强内容。

## D-010：商业化采取渐进路线

- **决定**：先验证一次性买断的本地桌面软件价值；云端 GPU 转写、跨设备同步等功能后续可作为 Pro 或按量服务评估。
- **原因**：先以低运营成本检验付费意愿，避免在产品价值未验证前引入持续云成本。
- **后续影响**：首版必须具备离线核心价值，任何云端能力均应为可选增强。

## D-011：首版摘要采用用户自带 API Key（BYOK）

- **决定**：首版不提供内置模型额度或自营摘要服务；用户自行配置 API Key，并选择其希望使用的模型服务。
- **原因**：先验证“视频转结构化知识”的产品价值，避免过早引入账户、支付、云端成本和模型运营复杂度。
- **后续影响**：应用需安全保存用户密钥，并将模型提供方设计为可扩展配置；后续可增加内置额度和平台托管 Key，但不改变核心摘要流程。

## D-012：个人测试版 API Key 使用本机明文存储

- **决定**：因 macOS Keychain 在当前测试环境中无法可靠写入，个人测试版将 API Key 明文保存在本机应用 SQLite 配置中，并在界面与隐私说明中明确风险。
- **原因**：优先保证个人工具的可用性与可验证性；用户已明确接受该本地存储取舍。
- **后续影响**：公开销售或多人使用前必须恢复到可靠的系统安全存储或引入用户账户加密方案；明文存储不作为正式发行版的长期方案。
