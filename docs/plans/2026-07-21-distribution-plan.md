# 快看视频 QuickVideo：发布与分发策略

**状态**：已确认  
**日期**：2026-07-21  
**适用阶段**：Apple Silicon Mac MVP 至首次商业验证

## 决策摘要

第一版不以 Mac App Store 为主发布渠道，而是以官网直接销售的 macOS App 验证产品价值。产品保留“分析链接”的核心体验，但不以下载或保存完整视频为卖点；本地文件导入作为稳定且长期存在的主路径。未来视平台授权、产品稳定性和商业验证结果，推出功能范围更受约束的 Mac App Store 版本。

## 已确认的四项规划

### 1. 第一版通过官网直接销售已签名、已公证的 macOS App

- 交付形态为标准 macOS 安装包（如 DMG）。
- 发布前使用 Apple Developer ID 签名，并完成 Apple notarization（公证）。
- 首版面向 Apple Silicon Mac，优先服务个人用户。
- 商业模式先验证一次性买断；不在本阶段建设用户账户、订阅和云端计费体系。

**原因**：可以完整验证“粘贴链接即可获得结构化视频笔记”的工作流，避免 Mac App Store 审核、内购、更新机制和链接来源授权要求过早限制产品设计。

### 2. 保留链接分析体验，但不宣传或承诺视频下载

- 用户入口命名为“分析链接”，而非“下载视频”。
- 优先获取平台提供且可用的字幕。
- 必要的媒体获取仅作为本地转写的后台临时步骤。
- 默认在任务完成后删除临时音视频，仅保留用户选择保存的字幕、章节摘要与笔记。
- 不将完整视频保存、转换、分发或“下载任意视频”作为产品卖点或营销文案。

**原因**：产品的长期价值是视频理解与知识沉淀，而非媒体文件本身；这样能降低版权、平台兼容性、存储和售后风险。

### 3. 将合规边界做成产品规则

- 仅允许用户处理其拥有、已获得授权或平台允许处理的内容。
- 不支持绕过 DRM、付费、会员、登录或其他访问限制。
- 首版在链接分析前和隐私/使用说明中明确上述限制。
- 处理失败时应明确说明原因，而不是尝试规避限制。

**原因**：YouTube、Bilibili 等第三方平台的内容访问规则和版权约束会持续变化。清晰边界是商业发布的基础，而非事后补充。

### 4. 预留未来的 Mac App Store 专用版本

- Mac App Store 版首先只支持本地视频/音频导入、本地转写、章节摘要和 Markdown 导出。
- 只有获得第三方服务明确授权，且完成单独审核评估后，才考虑加入相应的平台链接能力。
- App Store 版本与官网版可以共享大部分核心能力，但允许在来源支持范围上不同。

**原因**：Mac App Store 对第三方服务访问、音视频下载、沙箱、应用内解锁和更新机制有额外要求。专用版本可保留上架可能性，不使首次商业验证被审核不确定性阻塞。

## 当前产品矩阵

| 能力 | 官网直销版（第一版） | Mac App Store 预留版 |
|---|---|---|
| 本地视频/音频导入 | 支持 | 支持 |
| 本地 `whisper.cpp` 转写 | 支持 | 支持 |
| 用户自带 API Key 摘要 | 支持 | 支持（发布前复核） |
| Markdown 导出 | 支持 | 支持 |
| YouTube/Bilibili 链接分析 | 在授权与使用边界内支持 | 默认不支持 |
| 保存完整视频作为功能 | 不支持 | 不支持 |
| 自建更新机制 | 可规划 | 不支持，使用 App Store 更新 |
| 授权码/买断验证 | 可规划 | 不支持，使用 App Store 定价/内购规则 |

## 未来复盘触发条件

出现以下任一情况时，重新评估本规划：

1. 个人 MVP 已稳定使用，并有明确的外部付费意愿。
2. 计划公开销售或新增链接来源时。
3. 计划上架 Mac App Store 时。
4. 平台条款、内容访问方式或 Apple 审核规则发生重大变化时。
5. 从本地转写扩展到自营云端转写或摘要服务时。
